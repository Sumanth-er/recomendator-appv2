# Why these versions and not others:
#
# opentelemetry-api / -sdk 1.41.0 and the -instrumentation-* 0.62b0 packages
#   are one release train. The instrumentation packages pin each other with ==,
#   so bumping one alone does not resolve. google-adk 1.36.2 additionally caps
#   api and sdk at <=1.41.1, so 1.41.0 is at the top of what it allows.
#
# opentelemetry-exporter-gcp-logging has no stable release at all - only
#   pre-releases - so the a0 suffix is deliberate rather than an accident. An
#   unpinned line installs it only because pip falls back to a pre-release when
#   nothing stable exists, which is not a property worth depending on.
#   google-adk caps it at <=1.12.0a0. Needed only when OTEL_LOGS_EXPORT=1, but
#   pinned regardless so the build does not vary with that setting.
#
# opentelemetry-exporter-gcp-trace 1.15.0 requires resourcedetector-gcp <1.15,
#   which is why the detector is pinned rather than left to resolve.
#
# google-adk pulls the three gcp exporters in itself. They are listed here
#   anyway because app/telemetry.py imports them directly, and a dependency you
#   import should be a dependency you declare.
#
# Dropped: opentelemetry-instrumentation-logging. Nothing imported it - log
#   correlation comes from the formatter in app/main.py, which reads the span
#   context directly.
